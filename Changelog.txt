Release 1.5.2
=============
Every language it ships is now translated all the way through. Each of the
  eleven files had 39 strings with nothing in them, and Tamil had 169 of its
  193. These are machine translations rather than a speaker's work, so
  corrections are welcome and readme-translations.txt says how to send one
The window sizes itself to the language it is running in. It was laid out for
  English and carried a minimum width written by hand, and five translations
  needed more room than that: German, Spanish, French, Italian and Tamil all
  drew the "Show all devices" label with the end cut off. It now opens at
  whatever its own layout asks for, and refuses to be dragged narrower than it
  reads -- both worked out per language rather than written down
Ticking "Show all devices" no longer looks like the program has hung. It is the
  one control that can send a spun-down disk to fetch its size, which takes
  twelve seconds, and it did that with the tick not yet drawn and the status
  bar empty. The box is now ticked before the wait starts, the pointer says
  busy, and the status bar says what is being waited for
The status bar is empty when nothing is happening, instead of saying "Waiting
  for a task."
Both deploy scripts work out which DLLs a build needs the same way, through one
  function they share. Each also checks that the tool doing it is installed: a
  missing one used to be silent, and assembled a folder around an executable
  that could not start
The translation files no longer record which line of which file each string
  came from. Adding one string renumbered every string after it, so a one-line
  change arrived as a hundred-line diff in each of twelve files and the change
  itself had to be hunted for. Nothing ever read those numbers -- the compiled
  .qm files are identical without them

Release 1.5.1
=============
Sleeping hard disks are left alone. Filling the device list asked every disk on
  the machine how big it was, and a disk that has spun down takes twelve seconds
  to answer. Disks that will not be listed are now identified from what their
  drivers already hold and never woken, so with "Show all devices" unchecked no
  disk is touched at all
The window appears at once. That scan used to run before the window was created,
  so starting the program looked like nothing had happened until the platters
  were turning. It now runs behind a window that is already up, saying "Scanning
  disks..." for exactly as long as it takes
The device list is no longer rescanned every two seconds. It refreshes when the
  list is opened, when a device arrives or leaves, and when "Show all devices"
  is changed -- every moment its contents have to be right, and none in between
Qt's own strings -- dialog buttons, the file dialog -- are translated again in a
  natively built copy. The program asked for the per-module catalogue only, and
  windeployqt writes a merged one under another name, so those strings had
  quietly been English whoever built it
Reading a device to an image on a network share, or under a user name that is
  not ASCII, no longer abandons the free-space check and reports an error naming
  a drive nobody mentioned
The version number is written once, in src/CMakeLists.txt. The resource script
  kept its own copy of it, and the release job compares the tag against
  CMakeLists alone, so a shipped binary could disagree with its own release
tools/deploy.sh packages a build several times faster. It ran ntldd once per
  binary, which takes them all at once, and basename once per language per
  catalogue, which the shell does for nothing

Release 1.5.0
=============
Detects a partition table that Windows has already broken, and offers to put it
  right. Windows rewrites the primary GPT header's PartitionEntryLBA when it
  rescans a card written without "Fix GPT after write", leaving a header that
  passes its own checksum while pointing at sectors the partition entries are
  not in. Nothing that reads the primary table will accept it, and no data
  sector is touched -- so the card still matches its image exactly, and only
  the table says anything is wrong
The repair points PartitionEntryLBA back at the entries and rebuilds the header
  checksum. It is possible because the rewrite leaves PartitionEntryArrayCRC32
  alone, so the damaged header still records what the real entries hash to,
  which is what finds them again. No data sector is written
New "Check GPT" button looks at the selected device on its own, without an
  image and without writing or comparing anything: it reports whether the table
  is valid, absent, damaged, or unreadable, and offers the repair when it is
  damaged
Verify checks the table as well as the data, and no longer calls a run
  successful when the table is broken. Where the two differ only in the GPT and
  the table is sound, it now says so rather than blaming an option that may not
  have been used
"Fix GPT after write" and "Show all devices" moved into the Device group, under
  the device list, with the new button beside them. Everything to do with the
  device is in one place and the window is shorter for it
"Fix GPT after write" starts checked. Unchecking it once, for one card, used to
  be remembered for ever, leaving every later write open to the rewrite this
  program exists to prevent
Nothing is stored on the machine any more. The program kept an image directory,
  a file type and the GPT setting in the registry; it now keeps nothing, so a
  copy of it leaves nothing behind
The executable's icon is rendered from the SVG by the build on every platform,
  so the icon is edited in one place and never regenerated by hand. The render
  is deterministic: the same SVG produces the same bytes
Verify no longer reports a false failure after a successful GPT repair. The fix
  clears the stale backup GPT mid-device, and verify was comparing those
  cleared sectors against the image that still held the old copy
A checksum run that could not read the whole file reported the hash of the part
  it managed to read. A short read now says so
The Downloads folder is found again when the shell lookup fails, instead of
  falling back to whatever directory the program happened to start in
Fixed a mismatched free of the path returned by SHGetKnownFolderPath
Collapsed a great deal of repeated code: one failure epilogue instead of
  twenty-five copies, one device-acquisition path shared by write and verify,
  one error reporter instead of ten copies of the same Win32 boilerplate. One
  of those copies leaked its message buffer, and all ten read the error code
  after the call that could overwrite it
README restructured: the tool describes itself before it describes the defect
  it was written for

Release 1.4.1
=============
Tooltips are sized correctly again, without flickering. 1.4.0 wrapped the long
  ones in an HTML table of a fixed width, which padded every wrapped tooltip
  out to that width whether it needed it or not; and being rich text, it left
  Qt sizing the reused tooltip label through a document that kept the previous
  tooltip's width, so the text was clipped at both ends. They are plain text
  with line breaks in them now, and size to their widest line and nothing more
Dropped the workaround that hid the tooltip Qt was about to reuse. With the
  real cause gone it earns nothing, and it was what made a tooltip flash on and
  off as the pointer crossed the edge of a widget
The Generate and Copy buttons no longer carry the button's own padding inside
  their tooltips. A stylesheet set on a widget is inherited by that widget's
  tooltip, so those two tooltips sat 16 pixels wider than their text
Generate and Copy show that they have been pressed. That same stylesheet had Qt
  draw them itself instead of in the native style, which draws no pressed state
  unless one is written out. They are now the width of every other button,
  which the stylesheet had been shrinking them from
The browse button shows that it has been pressed. This style says "pressed" by
  dimming the button's label, and a button labelled only with an icon has
  nothing to dim -- its background was moving by one level out of 255
Added tools/gui-probe.ps1, which reports where the running window's widgets are
  and how wide the tooltip over one is, so a fault a few pixels wide can be
  measured instead of guessed at

Release 1.4.0
=============
New application icon: an SD card with a wrench across it, drawn as an SVG. The
  executable's .ico is generated from that one file by tools/mkicon, so the
  icon is edited as text rather than as a binary
The Write, Verify and Read buttons moved up between the Image File and Device

  the meaning without colour
The folder on the browse button is a modern outline drawing rather than the old

The progress bar reaches 100%. It was set from the first sector of the chunk it
  had just finished, so it stopped one chunk short and a 16 MB image finished
  at 96%
The progress bar is hidden until something is running, and the status bar says
  "Writing...", "Reading..." or "Verifying..." while it runs, instead of
  leaving "Clearing old partition tables..." up for the whole write
The status bar is shaded slightly against the window, so it reads as a part of
  the window rather than as blank space
Tooltips no longer appear clipped at both ends. Qt reuses one tooltip label and
  resizes it for the next tooltip; moving straight from a narrow tooltip to a
  wider one left the text cut off at the old width
Choosing an image selects SHA256, the checksum image publishers usually quote.
  A hash type chosen by hand is left alone
Paths are shown with backslashes, the way the rest of Windows writes them
The window is shorter, and the Image File Hash box no longer reserves a blank
  line for a checksum that has not been generated
The Verify button is labelled "Verify" rather than "Verify Only"
tools/make-test-images.sh also builds a GPT pair -- one image whose

Release 1.3.0
=============
Write and verify compressed images directly: a .img.gz or .img.xz is
  decompressed as it is written to the device, so no expanded copy is ever put
  on disk. Reading a device back still produces an uncompressed .img
The uncompressed size comes from the xz index, which is exact. gzip records it
  only modulo 4 GiB, so where it cannot be trusted the write runs until the
  stream ends and reports if the image did not fit
Format is decided by the file's magic bytes, not its name
A truncated or damaged compressed image is reported instead of being written
  out as far as it goes
A failed or cancelled write, read or verify now says so in the status bar and
  resets the progress bar, instead of leaving the last message on screen
An aborted write warns that the device holds a partial image and should be
  written again, which a decoder error on its own did not make clear
Added tools/make-test-images.sh, which builds raw, gzip and xz test images
  covering multi-member gzip, multi-stream xz, trailing padding, an image that
  is not a whole number of sectors, sizes past the 4 GiB gzip limit, and
  truncated and corrupt streams
Added tools/verify-flashed.sh, which compares a flashed device against its
  image byte for byte, whatever format it was written from

Release 1.2.0
=============
Identified the actual Windows defect behind the GPT corruption: on rescan it
  rewrites the primary GPT header's PartitionEntryLBA to FirstUsableLBA minus
  the entry array length, instead of leaving it pointing at the array. Images
  whose FirstUsableLBA is 34 are unaffected because that arithmetic returns
  the correct value by coincidence; ARM board images, which reserve space
  ahead of the first partition, are corrupted. See TESTING-GPT-BUG.md
The post-write dialog now states whether the image just written IS or IS NOT
  affected, computed from the image's own table rather than guessed
Added TESTING-GPT-BUG.md: a 48 MB reproducer and a Hyper-V VHDX harness that
  triggers the corruption on demand, without an SD card or an imaging tool
gptdump.py follows the primary header's AlternateLBA, so a backup GPT stranded
  mid-device is decoded instead of reported missing, and locates the entry
  array that a wrong PartitionEntryLBA no longer points at
Extra confirmation before writing to a device that has mounted drive letters
Removed "Read Only Allocated Partitions": it parsed only the MBR, so it did
  nothing useful on the GPT cards this tool is aimed at
Renamed the hash group to "Image File Hash" and its tooltip to match, since it
  hashes the image file and never the device
Device and hash dropdowns size to their contents; Device moved onto its own row
Updated all translation files for the new and changed strings
deploy.sh empties dist/ instead of deleting it, so an open Explorer window no
  longer breaks packaging

Release 1.1.0
=============
Fork release. Changes against 1.0.0:

Fixed the Windows GPT corruption that left written cards unbootable, and
  added the "Fix GPT after write" option; see README.md
Zero stale partition tables at both ends of the device before writing
Lock every volume on the target disk while writing, then offline and eject
  the disk before the locks are released
Removed the installer; updated to Qt 6
Added build notes, deploy scripts and a GitHub Actions workflow that
  cross-compiles for win64 from Linux
Enumerate physical disks instead of drive letters, so a device with no
  mounted volume — a card holding a Linux image, for one — still appears
Added the "Show all devices" option for internal card readers that present
  the card as a fixed, non-removable disk; the Windows system disk is never
  listed either way
Refresh the device list on a timer as well as on device-arrival broadcasts,
  since a card going into a reader that exposes no volume broadcasts nothing
Lock and dismount every volume on the disk for reads and verifies, as writes
  already did
Device list shows drive letters, size and model; the dropdown sizes itself to
  fit them
Report an error when the file for a checksum cannot be opened, rather than
  presenting the hash of nothing as valid
